Лекция 1: Введение в среду разработки и базовый синтаксис C#

1.1. Установка и настройка Unity Hub

Начало работы с игровым движком Unity и языком C# требует предварительной подготовки инструментария. Центральным элементом управления версиями и проектами является программа Unity Hub. Для её получения необходимо перейти на официальный сайт Unity и загрузить установочный файл. После завершения процесса установки и первого запуска перед пользователем открывается интерфейс лаунчера, который выполняет две ключевые функции: позволяет создавать новые проекты и управлять установленными версиями самого движка Unity. Важной особенностью Unity Hub является возможность параллельной установки неограниченного количества версий движка, что в будущем даст разработчику гибкость при работе с разными проектами. На данном этапе, перейдя в раздел «Installs», следует выбрать и установить актуальную версию Unity.

Особое внимание необходимо уделить выбору версии движка. В профессиональной среде настоятельно рекомендуется использовать исключительно версии с маркировкой LTS (Long Term Support), что переводится как «долгосрочная поддержка». Эти версии являются наиболее стабильными и проверенными, так как в них исправлено большинство критических ошибок, обнаруженных в промежуточных релизах. Игнорирование данной рекомендации может привести к возникновению трудноуловимых ошибок, источником которых является не пользовательский код, а внутренние недоработки самого движка. Следует помнить, что Unity разрабатывается такими же программистами, и вероятность наличия багов в нестабильных версиях достаточно высока. На начальном этапе обучения, столкнувшись с проблемой, всегда следует исходить из предположения, что ошибка находится в вашем коде, а не в движке.

В процессе установки выбранной версии необходимо внимательно проверить список устанавливаемых компонентов. Критически важным является наличие галочки напротив пункта Visual Studio. Visual Studio — это интегрированная среда разработки (Integrated Development Environment, IDE), которая предоставляет весь необходимый функционал для написания, отладки и компиляции кода на языке C#. После завершения установки обоих инструментов необходимо выполнить финальную настройку: в меню Unity (Edit → Preferences → External Tools) следует убедиться, что в качестве внешнего редактора скриптов выбрана именно Visual Studio. Существуют и другие, более продвинутые IDE, например, Rider от компании JetBrains, однако он является платным продуктом и не является обязательным для начинающего разработчика.

1.2. Создание проекта и структура скрипта

После завершения настройки среды необходимо создать первый проект. Для этого в Unity Hub нажимается кнопка «New Project», задается имя проекта, которое не влияет на функциональность, и указывается путь для его хранения на диске. После нажатия кнопки «Create» запускается редактор Unity с пустой сценой. Сцена — это пространство, в котором размещаются все игровые объекты.

Для начала работы с кодом необходимо создать скрипт. В иерархии сцены (окно Hierarchy) можно выбрать любой объект, например, «Main Camera», и в окне инспектора (Inspector) нажать кнопку «Add Component». В появившемся поисковом поле следует ввести желаемое имя для нового скрипта и нажать Enter. Созданный скрипт появится в виде компонента на выбранном объекте, а также в виде файла в папке «Assets» проекта. Двойной клик по файлу скрипта или по его названию в инспекторе откроет его в установленной IDE.

При первом открытии скрипта взгляду предстает шаблонная структура кода. В самом начале файла, как правило, находятся директивы using, подключающие стандартные библиотеки Unity. Далее следует объявление класса, имя которого совпадает с именем файла скрипта. Класс — это основной контейнер для всего кода в C#. Внутри класса находятся два метода: Start() и Update(). Код внутри фигурных скобок {} образует блок кода. Важно запомнить иерархию: код пишется внутри методов, а методы находятся внутри классов. На данном этапе все инструкции, написанные в блоке метода Start(), будут выполнены один раз в момент запуска сцены (при нажатии кнопки Play).

1.3. Синтаксис, компиляция и фундаментальные правила

Язык C# является строгим и формальным языком, где каждая деталь имеет значение. Понимание базовых принципов его работы является фундаментом для всего дальнейшего обучения.

Код выполняется последовательно, сверху вниз. Это означает, что инструкции, написанные в методе, будут обработаны процессором в том порядке, в котором они записаны, одна за другой.

Каждая отдельная инструкция в C# должна заканчиваться символом точки с запятой (;). Этот символ служит явным указателем для компилятора, что данная команда завершена, и можно переходить к обработке следующей. Компилятор — это специальная программа, которая переводит весь написанный человеком код с высокоуровневого языка C# на низкоуровневый машинный код, понятный процессору. Отсутствие точки с запятой является одной из наиболее частых синтаксических ошибок у новичков. К счастью, среда разработки (IDE) в реальном времени анализирует код и подчеркивает строки с ошибками красной волнистой линией. Важно выработать правильное отношение к ошибкам компиляции: это не признак поражения, а надежный и полезный инструмент, который точно указывает на локацию проблемы, позволяя быстро ее идентифицировать и исправить. Профессиональный рост программиста напрямую коррелирует с количеством успешно решенных им проблем.

Любой текст, предваренный двумя символами косой черты (//), превращается в комментарий. Комментарии — это участки кода, которые полностью игнорируются компилятором. Они служат исключительно для пояснений, заметок или заметок программиста.

C# является регистрозависимым языком. Это означает, что с точки зрения компилятора строчные (маленькие) и прописные (заглавные) буквы — это абсолютно разные символы. Команда debug.log не будет распознана, так как правильное написание — Debug.Log. А переменные Transform и transform (со строчной буквы) — это две разные, не связанные друг с другом сущности. Первая — это название типа (класса) компонента, а вторая — это встроенное свойство, предоставляющее доступ к компоненту Transform текущего объекта. Путаница в регистре может приводить к трудноуловимым логическим ошибкам, когда код компилируется, но работает не так, как задумывалось.

В помощь разработчику IDE предоставляет функцию автозаполнения кода (IntelliSense). Если начать вводить название команды или переменной, среда предложит список подходящих вариантов, что позволяет избежать опечаток и ускоряет процесс написания кода. На этом этапе все инструкции будут размещаться в блоке метода Start(). Попытка написать код вне допустимых блоков, например, непосредственно внутри класса, но за пределами метода, приведет к ошибке компиляции. Каждая открывающая фигурная скобка { должна иметь парную ей закрывающую }. Несоблюдение этого правила также приводит к синтаксическим ошибкам.

void Start()
{
    Debug.Log("Привет, мир!");
}

Лекция 2: Переменные и система типов данных

2.1. Понятие переменной как ячейки памяти

Центральным понятием в любом языке программирования является переменная. В наиболее простом и наглядном понимании, переменная — это именованная ячейка в оперативной памяти компьютера, предназначенная для хранения каких-либо данных. Можно провести аналогию с коробкой, на которую наклеена бирка с названием. Название (имя переменной) позволяет нам обращаться к этой коробке и взаимодействовать с её содержимым, не задумываясь о том, в каком именно физическом месте памяти она находится. Данные — это любая информация, которой оперирует программа: числа, буквы, слова и т.д.

Использование переменных не является просто удобством, а представляет собой фундаментальную необходимость, обеспечивающую гибкость и поддерживаемость кода. Представим ситуацию, когда в коде игры в сотне различных мест используется значение скорости персонажа, например, число «10». Если напрямую вписать это число во все сто участков кода, то для балансировки игры и изменения скорости, скажем, на «8», программисту придется вручную найти и исправить каждое из ста вхождений. Если же число «10» один раз присвоено переменной с именем playerSpeed, и во всех ста местах используется имя этой переменной, то изменение скорости сведется к исправлению всего одной строки кода. Это принцип кеширования данных, являющийся краеугольным камнем эффективного программирования.

2.2. Синтаксис объявления и присваивания значений

Процесс создания (объявления) переменной подчиняется строгому синтаксису. Сначала указывается тип данных, который переменная будет хранить. Затем, через пробел, задается имя переменной. Инструкция завершается точкой с запятой.

int myNumber;

Важно понимать, что переменная не может быть абсолютно «пустой». Если при объявлении переменной ей не было присвоено начальное значение явно, то среда исполнения автоматически присвоит ей значение по умолчанию (default value). Для числовых типов данных, таких как int и float, этим значением является 0 (ноль).

Для того чтобы поместить конкретное значение в переменную, используется оператор присваивания, который обозначается знаком равно (=). Важно на концептуальном уровне отделять его от математического понятия равенства. В программировании эта конструкция читается справа налево: «переменной слева присвоить значение, указанное справа».

int myNumber;
myNumber = 5; // Переменной myNumber присвоено значение 5

Объявление переменной и ее инициализацию (первое присваивание) можно совмещать в одной строке:

int myNumber = 5;

После того как переменной присвоено значение, она может использоваться в других инструкциях, например, в методе Debug.Log(), который выводит переданное ему значение в консоль Unity (окно Console).

2.3. Правила именования и контекст существования

Выбор правильного имени для переменной — это важнейший навык, напрямую влияющий на читаемость и поддерживаемость кода. Имя переменной должно быть осмысленным и кратко отражать суть хранимых в ней данных. Категорически запрещается использовать бессмысленные имена вроде a, b, x1, temp. Следует всегда помнить правило: «Код чаще читают, чем пишут». Сам автор кода спустя несколько недель не сможет понять, что хранилось в переменной x2, и будет вынужден тратить время на расшифровку собственных намерений.

Общепринятым стандартом именования в C# является стиль camelCase («верблюжья нотация»): имя переменной пишется слитно, при этом первое слово начинается со строчной (маленькой) буквы, а каждое последующее слово в составе имени — с заглавной (большой). Пример: playerHealth, moveSpeed, numberOfCoins. Начинать имя переменной с цифры запрещено на уровне синтаксиса языка.

Следует также понимать контекст существования переменной, или её область видимости (scope). Переменная, объявленная внутри одного метода (например, Start), существует только в пределах фигурных скобок этого метода и недоступна из другого метода (например, Update) или из другого класса. Попытка обратиться к такой локальной переменной извне приведет к ошибке компиляции. Переменные, объявленные непосредственно в теле класса, но вне каких-либо методов, называются полями класса и доступны (с учетом модификаторов доступа) из любого метода этого класса. Общепринятой практикой является размещение всех полей класса в самом его начале, перед объявлением методов.

2.4. Базовые арифметические и составные операторы

Над числовыми переменными можно производить все стандартные арифметические операции. Для увеличения значения переменной на единицу часто используется оператор инкремента (++), а для уменьшения на единицу — оператор декремента (--). Записи myNumber = myNumber + 1;, myNumber += 1; и myNumber++; являются полностью эквивалентными по результату.

Для выполнения более сложных арифметических действий с присваиванием существуют составные операторы присваивания. Они делают код более лаконичным и читаемым. Например, чтобы прибавить к переменной число 3, а не 1, можно написать myNumber += 3;. Это является сокращенной записью для выражения myNumber = myNumber + 3;. Аналогично работают операторы -=, *=, /=. Рекомендуется активно использовать их в своей практике, так как они являются стандартом в профессиональной разработке.

2.5. Обзор фундаментальных типов данных

Каждая переменная характеризуется строго заданным при объявлении типом данных. Этот тип нельзя изменить. Тип определяет, какие именно значения может хранить переменная и какой объем памяти для нее будет выделен.

  • int (Integer): Предназначен для хранения целых чисел как положительных, так и отрицательных. Например: -5, 0, 10, 250. Используется для всего, что по своей природе не может быть дробным: количество жизней, набранные очки, количество патронов и т.д. Попытка присвоить переменной типа int число с плавающей точкой (например, 3.14f) приведет к ошибке компиляции.
  • float (Floating-point number): Предназначен для хранения чисел с плавающей точкой, то есть дробных чисел. Является основным типом для работы с вещественными числами в Unity. Например: 36.6f, -10.0f, 0.01f. Ключевой особенностью синтаксиса является требование явно указывать суффикс f (или F) после числового значения, чтобы компилятор однозначно определил его как float: float temperature = 36.6f;. Это уменьшает вероятность неоднозначности и считается хорошим тоном даже при присваивании целых чисел: float speed = 5f;. Тип float может без проблем хранить целые числа, однако переменная типа int не может принять значение float. Существует иерархия: float является более «вместительным» типом данных.
  • bool (Boolean): Логический тип данных, который может принимать только одно из двух значений: true (истина) или false (ложь). Является фундаментом для построения всей логики ветвления в программах. Значением по умолчанию для bool является false. При именовании булевых переменных принято использовать префикс is, за которым следует глагол или прилагательное в вопросительной форме, например: isDead, isGrounded, isGameOver. Переменной типа bool можно присвоить не только явное значение true или false, но и результат логического выражения или сравнения: bool isEqual = (2 + 3 == 5); (переменная isEqual получит значение true).
  • string (String): Строчный тип данных, предназначенный для хранения текста — последовательности любых символов (букв, цифр, знаков). Текстовые литералы всегда должны быть заключены в двойные кавычки "". Значением по умолчанию для string является null, что означает отсутствие какого-либо значения. Это важная концепция: «отсутствие информации» в программировании — это тоже информация особого рода. Оператор + для строк выполняет функцию конкатенации (объединения). Если мы хотим объединить текст со значением переменной другого типа, компилятор автоматически преобразует это значение в его строковое представление. Чтобы внутри строки выполнить математическую операцию, а не просто вывести числа, это выражение необходимо заключить в скобки.

Неявная типизация (var): Ключевое слово var позволяет объявить переменную без явного указания типа, если ей сразу присваивается значение. Компилятор сам определит тип переменной по типу присваиваемого выражения. var number = 5; — переменная number станет типа int. var text = "Hello"; — переменная text станет типа string. Переменная типа var не может быть объявлена без инициализации и не может быть полем класса. Её использование — это всего лишь синтаксический сахар для сокращения записи, реальный тип данных присваивается переменной один раз и не может быть изменен в дальнейшем.

Лекция 3: Условные конструкции и логические операции

3.1. Предназначение и синтаксис условных конструкций

Программа, которая просто выполняет инструкции последовательно одну за другой, обладает крайне ограниченной функциональностью. Для создания интерактивного и адаптивного поведения, способного реагировать на действия пользователя и изменения игрового мира, необходимы механизмы, позволяющие изменять ход выполнения программы в зависимости от тех или иных условий. Таким фундаментальным механизмом является условная конструкция if.

Ключевое слово if в переводе с английского означает «если». Синтаксис конструкции следующий:

  • Ключевое слово if.
  • Открывающая круглая скобка (.
  • Условие — выражение, результатом которого обязательно должен быть логический тип данных (bool).
  • Закрывающая круглая скобка ).
  • Блок кода, заключенный в фигурные скобки { }, который будет выполнен, если и только если условие истинно (true).
if (playerHealth > 0)
{
    Debug.Log("Персонаж жив.");
}

Внутренняя логика работы if предельно проста: она анализирует исключительно булево значение внутри круглых скобок. Если там оказалось true — блок кода внутри фигурных скобок выполняется. Если false — программа полностью игнорирует этот блок и переходит к следующей инструкции, следующей за закрывающей фигурной скобкой if.

Первое время начинающие разработчики часто склонны к чрезмерному использованию if, создавая длинные и запутанные цепочки условий, называемые «спагетти-кодом». На данном этапе обучения это абсолютно нормально и является частью процесса познания инструмента. По мере изучения более сложных алгоритмических паттернов и структур данных количество глубоко вложенных if будет естественным образом сокращаться.

3.2. Расширенные формы: else if и else

Для обработки ситуаций, когда основное условие ложно, существуют необязательные расширения базовой конструкции if.

Блок else if (иначе если) позволяет проверить другое условие, если все предыдущие оказались ложными. Он пишется сразу после закрывающей фигурной скобки предыдущего блока. Таких блоков может быть неограниченное количество.

Блок else (иначе) является завершающим. Он не содержит собственного условия и выполняется только в том случае, если ни одно из всех проверенных выше условий (if и всех последующих else if) не оказалось истинным.

Важнейшей особенностью связки if — else if — else является то, что выполнится только первый блок, условие которого окажется истинным. Как только такое условие найдено и его код выполнен, все последующие блоки этой цепочки игнорируются, даже если их условия тоже истинны. Проверка происходит строго последовательно сверху вниз.

if (score > 100)
{
    Debug.Log("Отлично!");
}
else if (score > 50)
{
    Debug.Log("Хорошо.");
}
else
{
    Debug.Log("Продолжайте стараться.");
}

3.3. Логические операторы: И, ИЛИ, НЕ

Для построения сложных, составных условий используются логические операторы, которые позволяют комбинировать несколько булевых выражений в одно.

  • Оператор && (И, AND): Результирующее выражение будет истинным (true) тогда и только тогда, когда все объединяемые им выражения истинны. Если хотя бы одно из них ложно (false), то и всё составное условие ложно. Например, if (isGrounded && jumpKeyPressed) будет истинным, только если персонаж одновременно и на земле, и нажата клавиша прыжка.
  • Оператор || (ИЛИ, OR): Результирующее выражение будет истинным, если хотя бы одно из объединяемых выражений истинно. Оно будет ложным только в том случае, если все выражения ложны. Например, if (health <= 0 || timeLeft <= 0) приведет к окончанию игры, если здоровье упало до нуля или истекло время.

Приоритет выполнения операторов таков: сначала выполняются все операторы &&, и только потом ||. Эту логику можно изменять с помощью группирующих круглых скобок, точно так же, как в математических выражениях. Например, (A && B) || C.

  • Оператор ! (НЕ, NOT): Это унарный оператор, который применяется к одному булеву выражению и инвертирует его значение. true превращается в false, и наоборот. Наиболее частое применение — проверка на неравенство: if (myNumber != 10). Эта запись эквивалентна if (!(myNumber == 10)), но является более лаконичной. Второй частый сценарий — инвертирование логической переменной для проверки противоположного состояния: if (!isDead) эквивалентно if (isDead == false). Проговаривание условий на естественном языке («если НЕ мертв») помогает быстро освоить этот оператор.

3.4. Условная конструкция switch

Для ситуаций, когда необходимо сравнить одну и ту же переменную с несколькими различными конкретными значениями, существует более элегантная и читаемая альтернатива цепочке if — else if — конструкция switch.

Синтаксис switch:

  1. Ключевое слово switch, после которого в круглых скобках указывается переменная или выражение, значение которого будет сравниваться.
  2. Блок кода в фигурных скобках, внутри которого описываются отдельные случаи — case.
  3. Каждый case начинается с ключевого слова case, за которым следует конкретное значение для сравнения и двоеточие (:). Если значение переменной switch совпадает со значением в case, выполняется код, следующий за двоеточием.
  4. В конце блока кода для каждого case обязательно ставится ключевое слово break с точкой с запятой (break;). Оно означает выход из конструкции switch. Без него компилятор выдаст ошибку.
  5. Необязательная секция default (по желанию может размещаться в конце, что является общепринятой практикой). Она выполняется в том случае, если ни одно из значений case не совпало с проверяемым значением. Аналог блока else для switch.
switch (weaponType)
{
    case "sword":
        Debug.Log("Ближний бой");
        break;
    case "bow":
        Debug.Log("Дальний бой");
        break;
    default:
        Debug.Log("Неизвестное оружие");
        break;
}

switch поддерживает работу не только с целочисленными типами, но и со строками и некоторыми другими типами. Его использование делает код более структурированным и легко читаемым, когда логика программы зависит от конкретных фиксированных значений одной переменной.

Лекция 4: Методы, параметры и область видимости

4.1. Концепция метода и декомпозиция задач

По мере роста проекта размещение всего кода в одном единственном методе Start быстро приводит к хаосу. Код становится нечитаемым, его невозможно отлаживать и повторно использовать. Решением этой проблемы является декомпозиция — разбиение большой, сложной задачи на множество маленьких, простых и изолированных подзадач. В C# для оформления таких подзадач используются методы (также иногда называемые функциями, что в данном контексте является синонимом).

Метод — это именованный блок кода, который выполняет одну четко определенную операцию. Представьте пульт управления телевизором. Нажатие кнопки «Увеличить громкость» запускает метод IncreaseVolume(). Пользователю не нужно знать, как именно внутри телевизора обрабатывается сигнал и усиливается звук. Ему важен только результат и простой интерфейс для его вызова. Аналогично, в программировании метод Shoot() должен заниматься всей логикой выстрела, а код, отвечающий за обработку нажатия игроком на кнопку мыши, должен просто вызвать этот метод Shoot(), не вдаваясь в его внутренние детали.

Это дает три важнейших преимущества:

  1. Читаемость: Код, разбитый на методы с понятными именами, читается как техническое задание. Вместо сотни строк непонятного кода мы видим вызовы MoveCharacter(), CheckCollision(), PlaySound(), что делает логику программы очевидной.
  2. Повторное использование: Если метод один раз написан, его можно вызывать из любого другого места программы столько раз, сколько потребуется, без необходимости копировать один и тот же код. Дублирование кода — один из главных признаков плохой архитектуры.
  3. Упрощение отладки: Если возникает ошибка, связанная, например, с выстрелом, разработчик точно знает, что искать проблему нужно внутри метода Shoot(), а не анализировать весь огромный блок кода.

4.2. Синтаксис объявления методов, возвращающих значение и void

Объявление метода включает в себя несколько обязательных элементов в строгой последовательности:

  1. Тип возвращаемого значения: Это тип данных, который метод передаст обратно в точку своего вызова. Это может быть int, float, string, любой другой тип или даже ссылка на класс.
  2. Имя метода: Имя должно быть глаголом или глагольной фразой, записанной в стиле PascalCase (каждое слово с заглавной буквы, например: CalculateDamage, GetPlayerName), и четко отражать действие, которое метод выполняет.
  3. Круглые скобки (): Обязательный элемент, отличающий метод от переменной. Внутри них могут быть объявлены параметры.
  4. Тело метода: Блок кода, заключенный в фигурные скобки {}, который выполняется при вызове.

Существует два ключевых типа методов. Первый — метод, который не возвращает никакого значения. Для него в качестве типа возвращаемого значения используется ключевое слово void (в переводе с английского — пустота). Его задача — просто выполнить набор инструкций.

Второй тип — метод, который возвращает значение. В этом случае вместо void указывается конкретный тип данных. Такой метод обязан содержать в своем теле хотя бы одну инструкцию return, после которой указывается значение того же типа, что и тип возвращаемого значения метода. Как только исполнение доходит до оператора return, метод немедленно завершает свою работу и передает указанное значение обратно.

// Метод, который ничего не возвращает
void SayHello()
{
    Debug.Log("Hello!");
}

// Метод, который возвращает целое число
int GetSum(int a, int b)
{
    int result = a + b;
    return result; // Возвращаем вычисленное значение
}

Результат работы возвращающего метода можно использовать как значение: присвоить его переменной, передать в другой метод или напрямую вывести в консоль. Сам вызов метода осуществляется путем написания его имени с последующими круглыми скобками: SayHello();.

4.3. Параметры и аргументы метода

Методы, которые всегда выполняют одно и то же действие с одними и теми же данными, имеют ограниченную полезность. Гораздо мощнее создавать методы, поведение которых можно настраивать извне. Для этого служат параметры.

Параметры — это специальные переменные, которые объявляются в круглых скобках при определении метода. Они указывают, какие данные и какого типа метод ожидает получить для своей работы.

// Метод с двумя параметрами типа int
void DealDamage(int damageAmount, int targetHealth)
{
    // ... логика нанесения урона
}

Когда мы вызываем метод, мы должны передать в него конкретные значения для каждого параметра. Эти конкретные значения называются аргументами. Типы, количество и порядок аргументов должны строго соответствовать параметрам, объявленным в методе.

int enemyHealth = 100;
int weaponDamage = 15;
DealDamage(weaponDamage, enemyHealth); // Вызов метода с передачей аргументов

Параметры позволяют преодолеть барьер области видимости. Переменные, объявленные внутри одного метода (например, weaponDamage и enemyHealth из примера выше), не видны и не могут быть использованы в другом методе. Чтобы метод DealDamage смог с ними работать, их значения должны быть переданы ему в качестве аргументов через механизм параметров. Количество параметров у метода может быть любым, включая полное их отсутствие.

4.4. Понятие контекста и области видимости

Подробное понимание того, где существует та или иная переменная, критически важно для избежания трудноуловимых ошибок. Область видимости (scope) переменной — это тот участок кода, в пределах которого к этой переменной можно обратиться по имени.

Правила определения области видимости базируются на фигурных скобках { }:

  • Переменная, объявленная внутри метода (в том числе внутри Start, Update или любого другого пользовательского метода), существует и доступна только в пределах блока этого метода, от точки объявления до закрывающей фигурной скобки. Она называется локальной переменной.
  • Переменная, объявленная в блоке if или for, существует только внутри этого блока.
  • Переменная, объявленная на уровне класса (вне какого-либо метода), называется полем класса. Она доступна из любого метода этого же класса.

Между разными методами, а тем более между разными классами, локальные переменные «не видны» друг для друга. Единственный легальный способ передать данные из области видимости одного метода в другой — это передать их в качестве аргументов и получить результат через return.

Таким образом, каждый блок кода, ограниченный фигурными скобками, создает свой собственный изолированный контекст. Понимание этого правила позволяет правильно проектировать архитектуру программы и избегать соблазна делать все переменные глобальными (доступными отовсюду), что является плохой практикой, ведущей к хаосу в больших проектах. Эксперименты с созданием переменных в разных местах и намеренным вызовом ошибок компиляции — лучший способ укрепить это понимание.

Лекция 5: Массивы и циклические конструкции

5.1. Статические массивы

Ранее мы оперировали отдельными переменными. Однако в программировании часто возникают задачи, требующие хранения и обработки не единичных, а целых наборов однотипных данных. Прямолинейное создание для каждого элемента отдельной переменной (int score1; int score2; ... int score100;) является крайне неэффективным и не масштабируемым решением. Для работы с упорядоченными коллекциями данных в языке C# служат массивы (arrays).

Массив — это структура данных, представляющая собой непрерывную область в памяти, содержащую фиксированное количество элементов одного и того же типа. Каждый элемент в массиве идентифицируется по его порядковому номеру — индексу. Ключевой особенностью индексации в C-подобных языках является то, что она начинается с нуля. Следовательно, первый элемент массива имеет индекс 0, второй — 1, и так далее.

Массив, который мы рассмотрим в первую очередь, является статическим. Это значит, что его размер (количество элементов) жестко фиксируется в момент создания и не может быть изменен в процессе выполнения программы.

Объявление статического массива включает в себя: тип данных, пару квадратных скобок [], имя переменной и, что обязательно, инициализацию.

// Объявление и инициализация массива на 5 целых чисел
int[] playerScores = new int[5];

Ключевое слово new создает экземпляр массива в памяти. При такой инициализации все 5 ячеек массива автоматически заполнятся значениями по умолчанию для типа int, то есть нулями (0). Часто массив требуется заполнить конкретными значениями сразу. Для этого можно использовать сокращенный синтаксис с фигурными скобками:

int[] playerScores = new int[] { 10, 25, 40, 5, 100 };

Доступ к конкретному элементу массива для чтения или записи осуществляется по его индексу, указываемому в квадратных скобках: playerScores[0] — для первого элемента. Попытка обратиться к индексу, который меньше нуля или больше или равен длине массива, приводит к критической ошибке времени выполнения IndexOutOfRangeException, которая немедленно прерывает работу программы. Эту ошибку следует запомнить, так как она является прямым указанием на логический просчет в работе с индексами. Для получения длины массива используется свойство .Length.

5.2. Динамические коллекции List<T>

Ограничения статических массивов, связанные с их неизменяемым размером, делают их неудобными в сценариях, когда количество элементов неизвестно заранее или меняется по ходу игры (например, инвентарь игрока). Для решения этой проблемы в C# предусмотрена мощная динамическая структура данных — обобщенная коллекция List<T> (произносится как «лист»).

List<T> является частью пространства имен System.Collections.Generic и, по сути, представляет собой «умный» массив, способный динамически изменять свой размер. Для его использования в начале файла скрипта должна быть директива using System.Collections.Generic;.

Объявление List похоже на объявление массива, но с использованием угловых скобок для указания типа элементов и без указания размера:

List<int> enemyHealthList = new List<int>();

Изначально такой список пуст (содержит 0 элементов). Для добавления нового элемента в конец списка используется метод .Add(). Для удаления первого найденного элемента с указанным значением — метод .Remove(). Для удаления элемента по его индексу — метод .RemoveAt(). Для полной очистки списка — метод .Clear(). Для вставки элемента в произвольную позицию по индексу со сдвигом всех последующих — метод .Insert(). Текущее количество элементов в списке можно получить через свойство .Count.

Выбор между массивом и List определяется задачей: если размер коллекции точно известен и не меняется, массив является более легковесным и производительным решением. Во всех остальных случаях следует использовать List, так как он предоставляет несравнимо большую гибкость, которая для разработчика игр-одиночки или небольшой команды практически всегда важнее микроскопической разницы в производительности.

5.3. Циклы для обработки коллекций

Массивы и списки были бы практически бесполезны без механизма, позволяющего быстро и единообразно обработать все хранящиеся в них элементы. Таким механизмом являются циклы (loops). Цикл — это конструкция, которая позволяет выполнять один и тот же блок кода многократно, пока некоторое условие остается истинным.

  • Цикл while (пока): Самая простая форма цикла. Он проверяет условие перед каждой итерацией. Если условие истинно (true), блок кода выполняется, затем условие проверяется снова. Если условие ложно (false) с самого начала, блок кода не выполнится ни разу. Опасность при использовании while — создание «бесконечного цикла», когда условие никогда не становится ложным, что приводит к зависанию программы. Чтобы избежать этого, внутри тела цикла обязательно должно выполняться действие, которое в итоге сделает условие ложным.
int i = 0;
while (i < 5)
{
    Debug.Log(i);
    i++; // Увеличиваем i, чтобы цикл когда-нибудь завершился
}
  • Цикл do...while (делай... пока): Отличается от while тем, что проверка условия происходит после выполнения блока кода. Это гарантирует, что блок кода выполнится хотя бы один раз, даже если условие изначально ложно.
  • Цикл for (для): Является наиболее распространенным циклом для работы с массивами по индексу, так как объединяет в своей конструкции оператор инициализации, условие и оператор изменения счетчика. Синтаксис: for(инициализация; условие; итерация). Он идеально подходит, когда количество итераций точно известно или определяется длиной массива.
for (int i = 0; i < myArray.Length; i++)
{
    Debug.Log(myArray[i]);
}

Этот код последовательно выведет все элементы массива myArray от первого (индекс 0) до последнего (Length - 1).

  • Цикл foreach (для каждого): Предназначен исключительно для простого и безопасного перебора всех элементов коллекции (массива или List), когда нет необходимости работать с индексом элемента напрямую. Он сам на каждой итерации извлекает следующий элемент и помещает его в объявленную вами переменную. Синтаксис: foreach(Тип имяПеременной in Коллекция).
foreach (int score in playerScores)
{
    Debug.Log(score);
}

foreach делает код более компактным и защищает от ошибки выхода за границы массива, но не позволяет изменять значения элементов в перебираемой коллекции в этом же цикле.

Лекция 6: Классы, взаимодействие компонентов и статические члены

6.1. Класс, скрипт и компонент: иерархия понятий

На данном этапе необходимо четко разграничить несколько фундаментальных для Unity понятий, которые часто смешиваются новичками.

  • Скрипт (.cs файл): Это всего лишь файл в операционной системе, текстовый документ, в котором хранится написанный нами код.
  • Класс (class): Это логическая конструкция внутри кода, «чертеж» или «описание», которое определяет, какими данными (полями) и поведением (методами) будет обладать некая сущность.
  • Компонент (Component): Это класс, который унаследован от специального базового класса MonoBehaviour. Только такие классы могут быть прикреплены к игровым объектам (GameObject) в сцене Unity.
  • Экземпляр класса (Instance) или Объект: Когда мы перетаскиваем скрипт-компонент на игровой объект в сцене, движок Unity создает конкретную копию этого класса в памяти по его «чертежу». Именно с этим экземпляром, а не с самим классом-чертежом, происходит вся дальнейшая работа. Если один и тот же скрипт повесить на 10 объектов, будет создано 10 независимых экземпляров класса, каждый со своим собственным набором полей.

Ключевым признаком того, что класс является компонентом и может быть назначен на GameObject, является наследование от MonoBehaviour. Классы, не наследующие от MonoBehaviour, не могут быть компонентами, но могут использоваться как обычные классы C# для хранения и обработки данных.

6.2. Обращение к другим компонентам и модификаторы доступа

Игровая логика в Unity — это всегда взаимодействие множества компонентов. Скрипту пули нужно сообщить скрипту врага о нанесении урона. Скрипт игрока должен обратиться к компоненту Animator для проигрыша анимации. Для этого необходимо уметь получать ссылки на другие экземпляры классов (компонентов).

Самый простой и контролируемый способ — публично объявить поле нужного типа в своем скрипте. Это позволит в окне Inspector в Unity перетащить в это поле нужный игровой объект. Unity автоматически найдет на нем компонент требуемого типа и сохранит ссылку на него. Для этого используется ключевое слово public — один из модификаторов доступа. public означает, что к полю или методу можно обратиться откуда угодно: из других методов этого же класса, из других классов, а также что оно будет видно в инспекторе Unity.

Противоположностью public является модификатор private (или отсутствие модификатора, что по умолчанию делает поле приватным). private-поля доступны только для кода внутри того же самого класса. Сокрытие внутренней реализации класса (инкапсуляция) является важнейшим принципом, предотвращающим хаотичное изменение данных извне.

Для получения ссылок во время выполнения игры, когда связь через Inspector невозможна, существуют специальные методы класса GameObject. Поиск следует выполнять один раз в методе Start и сохранять результат в переменную, так как эти операции затратны. Варианты поиска:

  • GetComponent<T>(): Ищет компонент указанного типа на том же самом игровом объекте.
  • FindObjectOfType<T>(): Ищет первый попавшийся экземпляр компонента указанного типа на всей активной сцене.
  • Семейство методов GetComponentInChildren<T>() и GetComponentInParent<T>() позволяют искать компоненты в иерархии вложенных объектов.

Злоупотреблять этими методами (особенно FindObjectOfType) не рекомендуется по соображениям производительности и надежности.

6.3. Статические члены класса

Обычные поля и методы принадлежат конкретному экземпляру класса. Изменение поля health у одного врага никак не влияет на health у другого. Но что, если нам нужна переменная, которая была бы единой и общей для всех экземпляров класса? Например, счетчик убитых врагов, единый для всего уровня. Для этого используется ключевое слово static.

static-поле или static-метод принадлежат не экземпляру, а самому классу как типу. В памяти компьютера такая переменная существует в единственном экземпляре для всего класса. Обращение к статическому члену происходит не через имя переменной-ссылки, а напрямую через имя класса: Enemy.DeathCount = 10;.

Это кардинально меняет поведение: если из любого скрипта любого врага увеличить Enemy.DeathCount на единицу, это изменение сразу же отразится для всех, кто читает эту переменную.

Статические методы работают по тому же принципу — вызываются через имя класса и не имеют доступа к нестатическим полям конкретного экземпляра (потому что им не передается ссылка this). Классическим примером статического метода является Debug.Log().

Статические поля и методы — это мощный и удобный инструмент, но использовать его следует осознанно, чтобы не создавать путаницы и жестких связей в коде. Статические члены не сериализуются Unity и их значение сбрасывается при перезапуске игры, если не предприняты дополнительные меры.

Рекомендации по чистому коду и именованию

В завершение теоретического курса критически важно обсудить не только то, как заставить код работать, но и то, как сделать его поддерживаемым, читаемым и надежным. Эти принципы в совокупности называются написанием чистого кода (clean code).

Правила именования, зафиксированные в соглашениях Microsoft и ставшие индустриальным стандартом, — это не бюрократическая прихоть, а инструмент коммуникации. Существует два основных стиля:

  • PascalCase: все слова в имени пишутся с заглавной буквы. Используется для имен классов, методов, свойств и публичных полей. (PlayerController, GetDamage, MoveSpeed).
  • camelCase: первое слово со строчной буквы, все последующие — с заглавной. Используется для имен локальных переменных и параметров методов. (playerSpeed, damageAmount, isDead).

Приватные поля класса часто предваряют знаком подчеркивания _ (_currentHealth), чтобы при чтении кода можно было мгновенно отличить поле класса от локальной переменной.

Основные заповеди чистого кода:

  1. Не использовать «голые» (магические) числа. Любое фигурирующее в коде число (кроме 0 и 1 в некоторых очевидных случаях) должно быть присвоено константе или переменной с осмысленным именем.
  2. Не писать избыточные комментарии. Хороший код является самодокументируемым. Если метод или переменная названы ясно и однозначно, пояснения к ним не нужны. Комментарий должен отвечать на вопрос «почему было сделано именно так?», а не «что делает эта строка?».
  3. Избегать дублирования кода. Если два или более участков кода выглядят похоже, их следует вынести в отдельный метод.
  4. Делать видимость по умолчанию минимальной. Все поля, которые не должны быть доступны извне, должны быть объявлены как private.
  5. Не боятся рефакторинга. По мере разработки понимание задачи улучшается, и старый код можно и нужно улучшать, переименовывать, разбивать на более мелкие части, чтобы поддерживать его в чистоте.

    }
    return min;

// Скрипт Enemy.cs
public static int totalEnemies = 0;
public int health = 50;

void Start()
{
    totalEnemies++;
}

void OnDestroy()
{
    totalEnemies--;
}

public void TakeDamage(int damage)
{
    health -= damage;
    Debug.Log("У врага осталось " + health + " здоровья");
    if (health <= 0)
    {
        Destroy(gameObject);
    }
}

// Скрипт EnemyCounter.cs
void Update()
{
    if (Input.GetKeyDown(KeyCode.Space))
    {
        Debug.Log("Живых врагов: " + Enemy.totalEnemies);
    }
}
